Platform thesis

Build agents like production systems, not chat windows.

AgentSwarm.in treats an AI coding agent as a controlled engineering runtime: context, model policy, tools, workspaces, memory, permissions, evidence and independent verification are explicit components.

Portable agent core

One architectural core designed to power IDE, CLI, desktop, web, mobile and CI surfaces without redefining execution semantics for every client.

Model fabric

Route by coding capability, privacy, context, latency and operator policy instead of binding engineering workflows to a single model vendor.

Tool governance

Filesystem, shell, Git, browser, database and MCP actions belong behind explicit permission, sandbox, approval and audit boundaries.

Local-first execution

Local models and local context are first-class design targets for private repositories, offline work and environments where external inference is not appropriate.

Evidence-led verification

Builds, tests, security checks and artifact hashes should determine completion. A model saying "done" is not a verification result.

Reusable skills

Turn successful, reviewed workflows into versioned skills with declared tools, inputs, policy requirements and verification criteria.

Execution architecture

Intent → evidence, with every boundary visible.

The control loop separates planning from execution and execution from verification. This makes agent behavior easier to inspect, restrict, resume and improve.

Specialized agents

The right agent mode for the engineering job.

Agent roles are composable behavior profiles—not fake employee theater. Each mode combines task intent, context strategy, tool scope, model policy and verification requirements.

P

Plan

Decompose complex goals, map dependencies, surface uncertainty and define acceptance criteria before code changes begin.

C

Code

Implement scoped changes across files while preserving repository conventions and explicit tool boundaries.

D

Debug

Trace failures through logs, tests and code paths, then produce evidence-backed hypotheses and fixes.

R

Review

Evaluate diffs for correctness, maintainability, regressions and missing tests without self-certifying the authoring agent.

S

Security

Inspect trust boundaries, unsafe tool use, injection paths, secrets exposure and dependency risk.

A

Ask

Explore a codebase or architecture without changing it—useful for onboarding, design review and repository understanding.

Model Context Protocol

MCP as a governed capability layer.

AgentSwarm.in models both MCP client and server roles so agents can consume tools and expose reviewed capabilities without turning tool discovery into unrestricted execution authority.

MCP client path

Discover server → capabilities → filter by policy ∩ agent tools → authorize ALLOW / ASK / DENY → execute tool call → evidence.

MCP server path

Export agent/skill capability → declare schema (typed inputs/outputs) → declare policy (permission + audit) → serve stdio / HTTP transport.

Local LLM first

Keep sensitive engineering context where it belongs.

Local inference is a first-class architecture target, alongside cloud providers. The model router can reason about privacy, hardware, context size and capability before choosing an execution path.

Local runtime landscape

Ollama — developer-local inference · vLLM — self-hosted serving · llama.cpp — portable GGUF runtime · LM Studio — desktop model endpoint

Routing dimensions

Privacy — repository classification · VRAM — hardware-aware fit · Context — required token window · Quality — task evaluation history

Security and sovereignty

Autonomy without unbounded authority.

Agentic engineering is powerful precisely because agents can act. AgentSwarm.in therefore puts permissions, sandboxing, secrets, network access, approvals and verification into the architecture rather than treating them as post-launch hardening.
